# PROBLEM TYPE

## Vulnerability Type

- Improper Access Controls / Unauthenticated Arbitrary Deletion (CWE-862)

## Root Cause

Every administrative action endpoint gates access with a Location header but no termination:

```php
// delete-product.php:3-13
if(empty($_SESSION['login_email']))
    { header("Location: login.php"); }   // no exit() — execution continues
else{ }
$id= $_GET['id'];
$sql = "DELETE FROM tblproduct WHERE ID=?";
$stmt= $dbh->prepare($sql);
$stmt->execute([$id]);
```

PHP continues executing after header(), so the DELETE always runs. The 302 response masks the destruction.

## Impact

Any unauthenticated visitor destroys products, categories, sales, stock, supplier and user records by guessing sequential IDs (ID parameters are plain integers), or deactivates arbitrary accounts. Integrity of the inventory/financial data is fully attacker-controlled.

# No login or authorization is required to exploit this vulnerability

# Vulnerability details and POC

Local instance 127.0.0.1:8160, no cookies sent:

```
baseline: SELECT COUNT(*) FROM tblproduct -> 3
GET /delete-product.php?id=2   -> HTTP 302 (login redirect header)
SELECT COUNT(*) FROM tblproduct WHERE ID=2 -> 0   (row destroyed)
```

Transcript: poc/F1-unauth-delete.txt (repeat run deleted a further row: 3->2->0 across two unauthenticated requests).

# Suggested repair

1. Terminate after redirect: `header('Location: login.php'); exit;` in every guarded endpoint.
2. Central authentication middleware instead of per-file header snippets.
3. CSRF tokens and soft-delete audit trails for destructive operations.
